01 · What Kaisey solves

Your Week Drifts Away From What Matters

It’s recruiting season. You’re meant to network, prep cases, keep up with classes and still sleep, and every one of those lives somewhere different: a syllabus, an inbox, a spreadsheet of coffee chats, a calendar. None of them knows about the others. So the week fills up with whatever got scheduled first, not with whatever matters most.

Four demands, one week

Academics

Coursework deadlines, group projects, and reading lists exist in a silo with zero connection to your recruiting calendar or energy levels.

Recruiting

Coffee chats, application deadlines, and interview prep scattered across email, spreadsheets, and calendar invites — often with hard deadlines that override everything.

Social Life

Club events, networking dinners, weekend trips — the first thing sacrificed when workload spikes, but the hardest to rebuild once dropped.

Wellness

Gym, sleep, mental health — always deprioritized until burnout hits, then suddenly the most urgent thing on the list.

01 · What Kaisey solves

One Intelligent Layer Across Everything

Kaisey reads your Google Calendar, reasons over it with OpenAI to work out what matters most right now, then makes the changes for you: adding, moving and removing events once you accept. Not a new calendar. A smarter layer over the one you already use.

Dynamic Priority Toggle

One tap shifts your entire day. Slide between Academics, Recruiting, Social, and Wellness modes — Kaisey re-ranks every event using the model's reasoning, not a simple sort. When a connected Oura readiness score is below 60, Wellness mode auto-activates.

Plain English In, Schedule Out

Describe your week the way you would to a person and Kaisey pulls the commitments out of it, proposes times against your real calendar, and writes the blocks back. The model can reason across all of them at once.

Optional Oura Ring Sync

Connect an Oura Ring and Kaisey pulls sleep, readiness and recovery through the Oura API, then feeds it into the ranking. Slept four hours? Wellness blocks get promoted and low-stakes meetings defer. It is wired end to end — OAuth, sync and cards — and entirely optional: everything else works without it.

Privacy-First, Session-Only

Calendar data is processed in-session and never persisted on any server. The model sees what it needs to reason about priorities, then the context is discarded. No data warehouse, no profile building.

03 · Design · decisions

What We Chose and Why

Authentication

Google OAuth → Instant Calendar Access

One sign-in gives Kaisey read and write access to Google Calendar with zero onboarding friction, so accepted suggestions land straight in your calendar. No separate account creation, no permission pop-ups later. Students are in under 10 seconds.

✓ Google OAuth Email / Password
Interaction

Toggle Over Manual Ranking

A four-mode selector beats a complex drag-and-drop ranking UI. One tap shifts the entire priority stack — fast enough to switch contexts mid-day between a lecture and a recruiting event.

✓ Priority Toggle Manual Ranking UI
Build Stack

Hosted APIs Over Custom Infrastructure

Every layer of Kaisey leans on a hosted service so the build stays focused on the product, not the plumbing. The OpenAI API handles reasoning. Oura's API streams biometrics. Google OAuth handles auth. And Claude Code + Figma MCP turn design specs into shipped components without manual handoff.

04 · Technical build

How OpenAI Powers Kaisey

The OpenAI API isn't a chatbot bolted onto a calendar. It's the reasoning core — every prioritization decision flows through structured tool calls, JSON-mode output, and a multi-source context window. Remove the model and there is no product.

Why an LLM, Not a Sorting Algorithm?

A sort/filter can reorder by category. But only a language model can reason across your calendar, what you tell it in plain English, and your biometric state at the same time — multi-source reasoning, not sorting.

What Oura Data Powers

Sleep score, readiness score, and activity deficit. A readiness score below 60 triggers automatic wellness promotion. High readiness + recruiting mode means the model stacks demanding events together.

Tool Use Pattern

Three functions do the work: extract_tasks() pulls commitments out of freeform text, propose_schedule() fits them around what is already booked, and calendar_action() writes the result back. Calendar and Oura data are gathered client-side and passed in as context.

Structured Output

The model returns ranked JSON: each event gets a priority score (0–100), a rank position, and a one-line rationale. The frontend renders this directly — the model's reasoning is the engine.

04 · Technical build

Under the Hood

Designed in Figma and built end to end as a single-page React app, with every sensitive call kept server-side.

Frontend

React 18 + Vite

TypeScript, Tailwind and shadcn/ui primitives, with Framer Motion for the logo and transitions. No router: views swap by state, and all state lives in one root component.

AI layer

OpenAI via a serverless proxy

gpt-4o-mini with function calling, reached through a Vercel serverless function so the API key never ships to the browser. A keyword engine takes over if the model is unavailable.

Calendar

Google Calendar, two-way

Google OAuth for sign-in, then every add, remove or replace flows through one handler that updates the screen and writes the change back to Google Calendar.

Health data

Optional Oura Ring

Oura OAuth and API for sleep and readiness, cached on the device. Low readiness promotes wellness blocks in the recommendations.

Privacy

Session-only data

Calendar data is processed in the session and not stored on a server. The model sees what it needs to reason about the week, then the context is gone.

Ship

Static deploy

Built with Vite to static files on GitHub Pages; the proxy deploys separately on Vercel. Design to code moved through Figma MCP and Claude Code.

The brain dump, as a state machine

Turning a paragraph into calendar blocks is seven explicit phases, so the student can correct things at each step and nothing is written until they accept.

  1. IDLEwaiting for text
  2. EXTRACTINGmodel pulls out tasks
  3. EDITINGstudent fixes category and length
  4. PROPOSINGmodel fits them around the week
  5. REVIEW_SCHEDULEproposed blocks shown in place
  6. REVISINGchanges asked for in chat
  7. ACCEPTEDwritten to Google Calendar
Long-term Potential

From Hackathon to Platform

This isn't a hackathon project that dies on Monday. Kaisey has a clear distribution path from campus pilot to platform — and every phase makes the product harder to replicate.

Phase 1 — Validate (Now)

Spring 2026 · 20 CBS students

Closed beta measuring daily active usage, toggle frequency, and whether students report fewer missed deadlines after 2 weeks.

Phase 2 — Deepen Integrations

Summer 2026 · API Partnerships

Richer calendar edits, like changing a whole recurring series and rescheduling across weeks, and an LMS integration so coursework deadlines arrive automatically instead of being typed in.

Phase 3 — Event Discovery via LinkUp

Fall 2026 · Luma + Meetup Integration

Connect to Luma (lu.ma) and Meetup (meetup.com) via LinkUp to automatically surface relevant recruiting events, hackathons, and networking mixers in your city. Kaisey auto-recommends events that match your priority mode and adds them to your calendar.

Phase 4 — Multi-University

Fall 2026 · 5 partner schools

Career services partnerships at 4–5 university programs. Each school adds scheduling pattern data that sharpens the model's reasoning.

Phase 5 — Beyond Students

2027 · Working professionals

The priority toggle generalizes to professionals, and the optional biometrics hook extends to any wearable with a public API.

Built with Claude Code (agentic dev), Figma MCP (design-to-component handoff), OpenAI API (reasoning), Oura Ring API (biometrics), and Google Calendar OAuth.
